# ADR 0002: Collision Protection and Monolithic Brewfile Workflow

- **Status**: Accepted
- **Date**: 2026-10-31

## Context

Running dotfiles setup on an unprovisioned or dirty machine often fails when pre-existing system default files (e.g., standard `~/.zshrc` or `~/.gitconfig`) trigger Stow collisions. Furthermore, Homebrew setup should match the user's exact dumped state (`brew bundle dump -f`) so updates to installed apps and casks remain standard and single-sourced.

## Decision

1. **Collision Protection**:
   - `install.sh` inspects pre-existing destination files before running `stow`. If a non-symlink target file exists, it will be moved safely to a timestamped backup directory (`~/.dotfiles.backup.<timestamp>/`).
2. **Single-Source Brewfile**:
   - Maintain the standard monolithic `Brewfile` generated by `brew bundle dump -f`, keeping formulas and casks together.
   - `install.sh` runs `brew bundle --file=brew/Brewfile` directly on macOS.
3. **Login Shell & Local Overrides**:
   - Ensure `zsh` is set as the active shell if not already set.
   - Inject `.local` hooks (`~/.gitconfig.local`, `~/.zshrc.local`) and ignore `*.local` across the repository.

## Consequences

- Workflows using standard `brew bundle dump -f` remain fully compatible without manual splitting.
- Setup runs idempotently without human intervention even on dirty `$HOME` states.
